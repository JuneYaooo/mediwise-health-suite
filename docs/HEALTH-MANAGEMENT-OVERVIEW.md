# MediWise Health Suite 健康管理总览

> [返回文档中心](README.md) · [查看 README](../README.md)

MediWise Health Suite 是面向支持 Skills 的 AI Agent 的个人本地健康助手，可运行在 Hermes、OpenClaw、Claude Code、Codex、WorkBuddy，以及其他能够加载 Skills、访问本地文件并执行脚本的 Agent 工具中。它把自然语言对话、报告图片、可穿戴导出和日常记录整理为可查询、可追踪、可备份的家庭健康档案。

这里的“家庭”指一个本地用户代管本人及多位家人的档案，不代表群聊或多人共享服务。

## 能力边界

MediWise 只提供健康信息的记录、整理、查询、展示、趋势汇总、用户设定或规则触发的提醒，以及就医前资料整理。它不提供诊断、治疗建议、用药建议、营养治疗建议、临床判断或其他医疗指导。

异常信息只来自原始报告中的明确标记、用户设置的阈值或既有提醒规则。系统不会据此给出处理方案；如需医学判断，应由专业医疗人员完成。

## 核心能力

### 健康档案

- 管理本人、父母、伴侣和孩子的独立档案。
- 记录症状、诊断、就诊、用药、检验和影像结果。
- 查询时间线、既往史、过敏史和当前用药。
- 就医前汇总近期变化与需要向医生说明的问题。

### 日常指标

- 血压、血糖、心率、体温、血氧、体重等指标。
- 指定时间范围的查询和趋势比较。
- 自定义参考范围、测量提醒和异常提示。
- 生成最近 N 天的健康记录卡片。

### 生活方式

- 饮食与营养来源查询。
- 体重、围度、运动目标和进度。
- 睡眠时长、分期和趋势。
- Apple Health 与 Gadgetbridge 文件导入。

### 健康译报

- 八个观察与叙事域：体重、睡眠、生命体征、摄入、活动、服药记录、记录行为和家庭记录。
- 各域只读取自己边界内的记录，按域内规则折叠同日条目，再陈述有记录日、次数、最新日期和数字方向；没有记录的日期保持空白。
- 体重译报是八域引擎的展示案例，不是产品边界。它保留原有稳健趋势路径，并可把同期已有的摄入、活动和睡眠记录并列观察。
- 八域共用 24 套单域模板，可导出自包含 HTML、动画 SVG 和 1080×1440 冻结 PNG；个人综合译报可把当前所有有有效记录的体重、睡眠、生命体征、摄入和活动域编成 1080×1920 MP4，并保留逐镜头 PNG。
- 默认脱敏；家庭记录域只读取不透明成员 ID 和日期，不读取姓名、关系或其他身份资料，不比较成员。
- 卡片只陈述记录，不把同期变化写成原因，不提供诊断、治疗建议、用药建议或营养治疗建议。

### 图片与 PDF

- 当前 Agent 能直接读取附件时，直接提取图片或 PDF 内容，不需要单独配置视觉模型。
- 当前 Agent 无法读取时，可由配置 Agent 添加本地 PaddleOCR 或可选视觉 fallback。
- 识别结果先展示给用户确认，再写入档案。
- 新的云端视觉能力只有用户明确同意并显式配置后才使用。

## 个人与家庭成员规则

所有档案都由当前这一个本地用户管理：

1. 默认先创建“姓名（本人）”。
2. 只有一个本人档案时，无姓名请求可以默认本人。
3. 添加第二位成员后，写入必须明确姓名。
4. 展示和确认统一使用“姓名（身份）”，例如“张建国（父亲）”。
5. “爸爸”“妈妈”等关系只有在档案中唯一时才能匹配。
6. 同名或同身份多人时必须进一步询问，不能猜。

示例：

```text
帮我创建本人档案，我叫林安。
帮我添加一位家庭成员：张建国，是我的父亲。
帮张建国记录今天血压 150/95。
```

同一 MediWise 数据目录不能用于群聊机器人或多人共同访问。

## 健康记录卡片

“健康记录卡片”是这一图片汇总能力的统一名称。用户说“健康简报”“健康小报”“最近身体怎么样”等口语时，Agent 可以将其识别为同一能力，但对外回复、标题和文档统一使用“健康记录卡片”。

```text
帮我生成最近 7 天的健康记录卡片。
帮我生成张建国最近 30 天的健康记录卡片。
帮我生成最近 7 天的家庭健康记录卡片。
```

个人版按实际数据展示：

- 姓名与身份。
- 时间范围。
- 告警、待办和健康提醒。
- 最新指标、记录次数、期初变化、最近日期和数据来源。
- 离线 SVG 趋势图。
- 饮食摄入、运动消耗、步数与睡眠。
- 按日期合并指标更新、饮食、运动、睡眠、就医、检验和检查的个人健康时间轴。
- 当前在用药。

个人版采用确定性的动态布局：用户明确关注的模块优先；普通概览先处理 alert、warning、明确标记异常与到期提醒，再按实际记录覆盖量安排模块顺序和重点面板。完全为空且与当前问题无关的模块会省略，用户明确询问的模块即使为空也保留清晰的空状态。

家庭版是成员状态看板，不展示时间轴。每位成员显示“姓名（身份）”、当前状态、有限的最新指标、在用药和服药计划、提醒与明确注意事项。有告警、明确异常或到期提醒的成员优先；均无风险时，再优先展示有在用药、计划提醒或近期记录的成员。明确请求家庭版时不要求指定单个姓名；普通个人请求在存在多位成员时仍必须确认姓名。

没有记录的项目显示暂无数据，不通过模型猜测或补造。饮食日均只除以实际有记录的天数，运动消耗不作为完整热量收支，项目没有饮水或临床液体出入量数据时不展示相关数值。检验异常只根据原始记录中的明确异常标记汇总。卡片只用于记录展示和提醒，不提供诊断、治疗、用药或其他医疗指导。

## 典型工作流

### 日常记录

```text
自然语言或文件输入
→ 解析目标成员
→ 提取结构化信息
→ 用户确认不确定项
→ 写入本地数据库
→ 查询趋势或生成健康记录卡片
```

### 就医前准备

```text
选择成员和时间范围
→ 汇总症状、指标、既往史、过敏史与在用药
→ 生成短文摘要
→ 按需导出图片或 PDF
```

### 可穿戴导入

```text
用户上传导出文件
→ 确认目标成员
→ 校验 Apple Health 或 Gadgetbridge 格式
→ 标准化指标与时间
→ 去重写入
→ 返回新增数、跳过数、指标和时间范围
```

## 数据来源状态

| 来源 | 状态 | 说明 |
|---|---|---|
| Apple Health XML / ZIP | 已验证 | 支持 Health App 导出文件 |
| Gadgetbridge SQLite | 已验证 | 支持本地数据库导入 |
| Garmin Connect | 实验性 | 非官方接口，不作为默认用户流程 |
| Huawei Health Kit | 暂不可用 | OAuth 回调尚未完成 |
| Zepp 云账号 | 暂不可用 | 账号兼容性和凭据流程未达发布标准 |
| OpenWearables | 暂不可用 | 当前仍是 Stub |

## 数据与隐私

- 医疗档案默认保存在 `medical.db`。
- 生活方式数据默认保存在 `lifestyle.db`。
- 数据库、配置、附件和备份不应提交到 Git。
- API Key、密码和 token 不通过聊天收集。
- 云端视觉模型会收到完整图片或 PDF 页面。
- USDA 与 Open Food Facts 只接收食物搜索所需参数，不接收成员或健康记录。
- 备份包含完整健康档案，应只保存在用户信任的位置。
