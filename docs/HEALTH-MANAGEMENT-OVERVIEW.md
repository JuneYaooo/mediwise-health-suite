# MediWise Health Suite 健康管理总览

MediWise Health Suite 是面向 OpenClaw 的个人本地健康助手。它把自然语言对话、报告图片、可穿戴导出和日常记录整理为可查询、可追踪、可备份的家庭健康档案。

这里的“家庭”指一个本地用户代管本人及多位家人的档案，不代表群聊或多人共享服务。

## 核心能力

### 健康档案

- 管理本人、父母、伴侣和孩子的独立档案。
- 记录症状、诊断、就诊、用药、检验和影像结果。
- 查询时间线、既往史、过敏史和当前用药。
- 就医前汇总近期变化与需要向医生说明的问题。

### 日常指标

- 血压、血糖、心率、体温、血氧、体重等指标。
- 指定时间范围的查询和趋势比较。
- 自定义参考范围、测量提醒和异常提示。
- 生成最近 N 天的健康记录卡片。

### 生活方式

- 饮食与营养来源查询。
- 体重、围度、运动目标和进度。
- 睡眠时长、分期和趋势。
- Apple Health 与 Gadgetbridge 文件导入。

### 图片与 PDF

- PaddleOCR 在本地提取普通图片和扫描 PDF 的文字。
- 可选视觉模型理解复杂版面、表格和图表。
- 识别结果先展示给用户确认，再写入档案。
- 云端视觉能力只有显式配置后才使用。

## 个人与家庭成员规则

所有档案都由当前这一个本地用户管理：

1. 默认先创建“姓名（本人）”。
2. 只有一个本人档案时，无姓名请求可以默认本人。
3. 添加第二位成员后，写入必须明确姓名。
4. 展示和确认统一使用“姓名（身份）”，例如“张建国（父亲）”。
5. “爸爸”“妈妈”等关系只有在档案中唯一时才能匹配。
6. 同名或同身份多人时必须进一步询问，不能猜。

示例：

```text
帮我创建本人档案，我叫林安。
帮我添加一位家庭成员：张建国，是我的父亲。
帮张建国记录今天血压 150/95。
```

同一 MediWise 数据目录不能用于群聊机器人或多人共同访问。

## 健康记录卡片

“健康记录卡片”是这一图片汇总能力的统一名称。用户说“健康简报”“健康小报”“最近身体怎么样”等口语时，Agent 可以将其识别为同一能力，但对外回复、标题和文档统一使用“健康记录卡片”。

```text
帮我生成最近 7 天的健康记录卡片。
帮我生成张建国最近 30 天的健康记录卡片。
帮我生成最近 7 天的家庭健康记录卡片。
```

个人版按实际数据展示：

- 姓名与身份。
- 时间范围。
- 告警、待办和健康提醒。
- 最新指标、记录次数、期初变化、最近日期和数据来源。
- 离线 SVG 趋势图。
- 饮食摄入、运动消耗、步数与睡眠。
- 按日期合并指标更新、饮食、运动、睡眠、就医、检验和检查的个人健康时间轴。
- 当前在用药。

家庭版显示成员数量、需要关注人数、每位成员的紧凑摘要，以及按日期合并的家庭就医、检验和检查时间线。成员始终显示为“姓名（身份）”。明确请求家庭版时不要求指定单个姓名；普通个人请求在存在多位成员时仍必须确认姓名。

没有记录的项目显示暂无数据，不通过模型猜测或补造。饮食日均只除以实际有记录的天数，运动消耗不作为完整热量收支，项目没有饮水或临床液体出入量数据时不展示相关数值。检验异常只根据原始记录中的明确异常标记汇总。卡片仅用于信息整理和趋势参考，不构成诊断。

## 典型工作流

### 日常记录

```text
自然语言或文件输入
→ 解析目标成员
→ 提取结构化信息
→ 用户确认不确定项
→ 写入本地数据库
→ 查询趋势或生成健康记录卡片
```

### 就医前准备

```text
选择成员和时间范围
→ 汇总症状、指标、既往史、过敏史与在用药
→ 生成短文摘要
→ 按需导出图片或 PDF
```

### 可穿戴导入

```text
用户上传导出文件
→ 确认目标成员
→ 校验 Apple Health 或 Gadgetbridge 格式
→ 标准化指标与时间
→ 去重写入
→ 返回新增数、跳过数、指标和时间范围
```

## 数据来源状态

| 来源 | 状态 | 说明 |
|---|---|---|
| Apple Health XML / ZIP | 已验证 | 支持 Health App 导出文件 |
| Gadgetbridge SQLite | 已验证 | 支持本地数据库导入 |
| Garmin Connect | 实验性 | 非官方接口，不作为默认用户流程 |
| Huawei Health Kit | 暂不可用 | OAuth 回调尚未完成 |
| Zepp 云账号 | 暂不可用 | 账号兼容性和凭据流程未达发布标准 |
| OpenWearables | 暂不可用 | 当前仍是 Stub |

## 数据与隐私

- 医疗档案默认保存在 `medical.db`。
- 生活方式数据默认保存在 `lifestyle.db`。
- 数据库、配置、附件和备份不应提交到 Git。
- API Key、密码和 token 不通过聊天收集。
- 云端视觉模型会收到完整图片或 PDF 页面。
- USDA 与 Open Food Facts 只接收食物搜索所需参数，不接收成员或健康记录。
- 备份包含完整健康档案，应只保存在用户信任的位置。

| `wearable-sync` | 可穿戴导出文件的校验、同步与去重 |
