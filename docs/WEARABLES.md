# 可穿戴数据导入指南

MediWise 当前把可穿戴能力分为“已验证可用”“实验性”和“暂不可用”。只有完成文件校验、导入、标准化写库和重复数据去重的来源，才会标记为已验证。

## 当前状态

| 来源 | 状态 | 说明 |
|---|---|---|
| Apple Health | 已验证可用 | 支持健康 App 导出的 `export.zip` 或 `export.xml` |
| Gadgetbridge | 已验证可用 | 支持其导出的 SQLite 数据库，具体指标取决于设备和表结构 |
| Garmin Connect | 实验性 | 依赖非官方接口和一次安全认证，不作为默认用户流程 |
| Huawei Health Kit | 暂不可用 | OAuth 授权回调尚未完成 |
| Zepp / 小米账号云同步 | 暂不可用 | 账号兼容性和凭据处理尚未达到稳定发布标准 |
| OpenWearables | 暂不可用 | 当前仍是未实现的接口占位 |

普通用户不需要运行 Python、Node.js、Shell 或其他命令。把文件交给 OpenClaw，再用自然语言说明要导入到哪位家庭成员即可。

## 导入 Apple Watch / iPhone 数据

### 1. 从 iPhone 导出

在 iPhone 上完成以下操作：

1. 打开“健康”App。
2. 点击右上角头像。
3. 选择“导出所有健康数据”。
4. 等待系统生成 `export.zip`，然后保存到“文件”App，或发送到你正在使用的 OpenClaw 会话。

导出包可能包含姓名、出生日期、设备信息和完整健康记录，请只发送给你信任的个人本地 OpenClaw，不要上传到公开群聊、Issue 或网盘分享链接。

### 2. 对 OpenClaw 说

上传导出包后发送：

```text
请把这个 Apple 健康导出包导入我的 MediWise 档案。
导入前先确认目标成员和文件格式；完成后告诉我：
1. 新增了哪些指标；
2. 每种指标各有多少条；
3. 数据覆盖的时间范围；
4. 跳过了多少重复记录；
5. 是否有无法识别的记录。
```

如果只有一个“本人”档案，可以默认导入给本人；如果已经建立多位家庭成员，OpenClaw 必须先询问姓名，并用“姓名（身份）”复述确认，不能自行猜测。

### 3. 正常结果应该包含

- 文件校验通过或明确说明失败原因。
- 新增条数和重复跳过条数。
- 实际导入的指标类型，而不是只说“同步成功”。
- 文件里没有某项数据时如实说明，不根据设备型号猜测。

Apple Health 是手动导出的数据快照，不是实时同步。需要更新时，重新从健康 App 导出并上传即可；MediWise 会跳过已经存在的同源同时间记录。

## 导入 Gadgetbridge 数据

Gadgetbridge 适合已经在 Android 上使用 Gadgetbridge 管理手环或手表的用户。设备是否兼容，以 [Gadgetbridge 官方支持列表](https://gadgetbridge.org/gadgets/) 为准；MediWise 不负责设备配对，也不会声称所有小米、Amazfit 或华为设备都能导入。

### 1. 从 Gadgetbridge 导出

在 Gadgetbridge App 中进入“设置”或“数据库管理”，选择导出数据库。不同版本的菜单名称可能略有差异，导出的文件通常是 `Gadgetbridge` 或 `Gadgetbridge.db`。

### 2. 对 OpenClaw 说

上传数据库后发送：

```text
请把这个 Gadgetbridge 数据库导入我的 MediWise 档案。
先只读检查数据库格式和可识别的数据表，不要修改原文件。
确认目标成员后再导入，并告诉我新增的指标类型、条数、时间范围和重复跳过数量。
```

MediWise 只读打开 Gadgetbridge 导出数据库，不应修改用户上传的原文件。当前解析器会识别部分常见活动表中的心率、步数、血氧和睡眠记录；具体可用项取决于设备型号、Gadgetbridge 版本和实际导出表结构。

## Garmin Connect 为什么是实验性

Garmin 接入使用非官方 Garmin Connect Web 接口，不是 Garmin 面向普通第三方应用提供的稳定 OAuth 集成。它还需要一次账号认证，而密码不能经过聊天、模型上下文或普通日志。

因此当前版本：

- 不把 Garmin 列为“已验证可用”。
- 不要求普通用户复制或运行认证命令。
- 不允许用户把 Garmin 密码发送给 OpenClaw。
- 没有安全的本地凭据输入能力时，不继续绑定。

等后续版本提供稳定、可验证且不需要用户运行代码的安全授权流程后，再把 Garmin 提升为正式支持。

## 暂不可用的来源

Huawei Health Kit、Zepp / 小米账号云同步和 OpenWearables 当前不能作为普通用户接入路径。即使代码中存在相应 Provider，也不代表授权、凭据安全、账号兼容性和完整导入链路已经达到可用标准。

当用户询问这些来源时，OpenClaw 应直接说明当前限制，不应让用户尝试未完成的 OAuth 流程、粘贴密码或运行调试脚本。

## 遇到问题时怎么说

不需要自己排查代码。把错误原文和文件名告诉具备本机访问权限的 AI 助手：

```text
请检查这次可穿戴导入为什么失败。只读取日志中的必要错误，不要输出健康数据、账号凭据或完整文件内容。请告诉我是文件格式不支持、文件损坏、设备表结构未识别，还是 MediWise 本身的问题；未经我确认不要修改原始导出文件。
```
