## 药物安全查询规则

凡是涉及以下问题，必须先查再答，不能凭记忆：

- 药物交互
- 用药禁忌
- 不良反应
- 药物 + 酒精
- 药物 + 食物
- 中成药安全

通过 DDInter、openFDA 或网页搜索查询，统一使用来源筛选、引用格式和免责声明。

## 查询方式

### DDInter

```bash
python3 {baseDir}/scripts/drug_interaction.py check --member-id <id> --drug-name "布洛芬"
python3 {baseDir}/scripts/drug_interaction.py check-pair --drug-a "阿司匹林" --drug-b "华法林"
python3 {baseDir}/scripts/drug_interaction.py lookup --name "奥美拉唑"
python3 {baseDir}/scripts/drug_interaction.py search --name "阿司匹林"
```

适合两种西药之间的交互检查。

### openFDA

```bash
python3 {baseDir}/scripts/openfda_query.py interaction --name "warfarin"
python3 {baseDir}/scripts/openfda_query.py check-pair --drug-a "warfarin" --drug-b "aspirin"
python3 {baseDir}/scripts/openfda_query.py search --name "metformin"
```

适合作为英文结构化补充验证来源。

### 网页搜索

- 中成药、安全说明、药酒同服、药食同服等优先走网页搜索
- 来源优先级：权威医学数据库 > 官方说明书 > 可靠医学网站
- 正文关键结论必须带 `[1][2]`

## 结果呈现

- 按权威来源原有等级展示严重、中等或轻微等风险标签，不自行升级或降低等级。
- 明确区分“来源中记录的风险”与 MediWise 的提醒，不能把查询结果表述成处方或临床判断。
- 不回答“可以吃/不可以吃”，不指示开始、停用、更换、合用或调整药物；相关决定由医生或药师判断。

每次药物安全类回复都要：

1. 展示查询到的风险标签和来源原文要点
2. 说明依据并标注编号引用
3. 列出真实来源链接
4. 明确说明本项目不提供用药建议，具体用药决定应咨询医生或药师

查不到时，直接说“未查到标准交互数据；MediWise 无法据此判断是否适合合用，请咨询医生或药师”。


### 强制：健康卡片默认发送 PNG

当用户要“健康卡片”，或使用“健康简报”“健康小报”等口语表达时，统一生成 PNG 健康卡片：

```bash
python3 {baseDir}/scripts/briefing_report.py screenshot --member-id <id>
```

拿到 `image_path` 后，使用当前 Agent 客户端的图片或附件发送能力发送：

```text
这是你的健康卡片：
[发送 image_path 指向的 PNG]
```

发送失败时说明当前客户端的具体限制，并保留本地图片路径；不要伪造已发送状态。

### 动态布局策略

默认使用 `focus=auto`，让生成器根据真实记录计算布局。不要在 Agent 回复中自行拼接 HTML，也不要用模型主观判断哪个数值异常。

布局按以下优先级决定：

1. 用户明确意图优先。用户问“血压趋势”“最近吃得怎么样”“最近检查结果”“现在吃什么药”“生成个性化健康卡片”时，分别传 `focus=metrics|lifestyle|care|medications`。
2. 未指定重点时，alert 高于 warning，明确标记异常和到期提醒高于单纯记录量。
3. 没有风险信号时，比较指标、生活方式、医疗记录和用药的实际覆盖量；只有明显领先时才选择单一重点，否则使用均衡布局。
4. 重点模块前置。指标重点时把被告警点名的指标排在最前并整宽展示；生活方式重点时放大饮食、运动或睡眠中记录覆盖最多的面板；医疗重点时把个人时间轴前置；用药重点时把在用药表前置。
5. 自动概览省略完全为空且与本次问题无关的模块。用户明确指定的模块即使为空，也保留空状态，清楚说明没有记录。

指标区只展示该指标已记录的内容：有两条以上记录时画趋势图，只有一条记录时退化成一行最新值（数值、记录条数、最近日期、来源），不写「记录不足，暂不判断趋势」，也不画只有一个点的图。

个人版支持的 focus：

| focus | 使用场景 | 版式行为 |
|---|---|---|
| `auto` | 普通健康概览、定时卡片 | 风险优先，再看覆盖量；返回 `layout_profile` |
| `metrics` | 血压、血糖、心率、体重等趋势 | 指标区前置，首张趋势图整宽，告警点名的指标排在前面 |
| `lifestyle` | 饮食、运动、步数、睡眠 | 生活方式区前置，覆盖最多的面板放大 |
| `care` | 就医、检验、检查 | 个人健康时间轴前置 |
| `medications` | 当前用药、服药提醒 | 在用药区前置 |

家庭版不接受手动 focus，也不展示家庭时间轴。它是按成员组织的状态看板，每张成员卡固定展示当前状态、有限的最新指标、在用药和服药计划、提醒与明确注意事项。生成器自动将有 alert 的成员排在最前，其次是 warning、明确标记异常和到期提醒；均无风险时，再按在用药、计划提醒和近期记录覆盖度排列。只有确有风险或到期待办的首位成员使用强化卡片样式。

### 指标趋势图

指标区的取数与卡片自身分开。时间轴、计数条、`coverage`、`risk` 仍按卡片的 `--days` 窗口计算，趋势图则固定回看最近 90 天（卡片窗口更长时按卡片窗口，即 `metrics_window_days`）。所以卡片可以写「最近 7 天」而图上仍有 90 天的记录：**图上的日期跨度以头部标注的为准**，不要按卡片表头的窗口去描述图。

每张图的构成是固定的：

| 位置 | 内容 |
|---|---|
| 头部 | 指标名（血压为「血压 收缩压/舒张压」）与单位；多序列时给图例；右侧 `{N} 条 · {首} 至 {末}` |
| 图内 | 数值刻度与浅色网格线、日期刻度、折线、数据点；点数 ≤6 时每点标数值，超过 6 点时只标首末两点 |
| 底部 | 最新一条记录的来源；记录数超过画图上限时，另标注「未绘入图表」的条数 |

- 只有血压是双序列（收缩压 / 舒张压）并带图例；血糖按记录里实际存在的上下文键（空腹 / 餐后 / 随机 / 测量值）各自成线；心率、体重、体温、血氧各一条线。
- 横轴按真实日期定位；同一天的多次测量按记录顺序铺开、不重叠，缺测的日期留空而不插值，也不连线补点。
- 记录过多时按固定规则等距抽取绘制，首末两条始终保留，抽取掉的条数如实标出，不静默丢弃；点太密时只保留每个序列的末点，避免圆点互相压叠。

**图上不做任何判断**：不画参考范围带，不按数值高低给点上色，不标「正常 / 异常 / 偏高」，折线与图例的颜色只用于区分序列、不表达好坏。是否异常只有两个来源，都写在卡片的其他区块里：原始报告的显式标记（H/L）和用户已配置的阈值告警。图表也不写「趋势向好 / 恶化」这类结论——方向由读者自己从点上读。

### 个人健康时间轴

时间轴按日期倒序合并就医、检验、检查、指标更新、饮食、运动和睡眠事件，最多 10 条（同一天内医疗事件在前）。每条事件只呈现记录中已有的结构化字段，**不打印粘贴进来的段落原文**：

| 事件 | 标题 | 正文 |
|---|---|---|
| 就医 | `visits.diagnosis`（无诊断时退到科室 → 就诊类型 → 未填写） | 就诊类型 · 医院 · 科室 · 主诉 · 该次就诊的测量值 |
| 检验 | `lab_results.test_name` | `{N} 项明确异常`，**逐项列出全部**带显式标记的检验项（名称 · 数值 单位 · 标记）；无显式标记时写「无明确异常标记」 |
| 检查 | `imaging_results.exam_name` | `imaging_results.conclusion`；没有结论时写「未填写」 |
| 指标更新 / 饮食 / 运动 / 睡眠 | 固定标题或记录名称 | 已结构化的数值 |

- 测量值只有通过 `health_metrics.related_visit_id` 明确指向该次就诊时才归入就医事件；**不按日期推断**——同一天的门诊就诊与居家自测是两次不同的测量，日期相近不构成归属证据。
- 已经画进就医事件的测量值不再单列为「健康指标更新」事件；未被归属的测量值仍保留自己的事件，不会静默消失。
- 现病史、入院查体、处理计划、影像所见等原文不上卡片；它们完整保留在数据库与 `query timeline` 的 JSON 中。

### 病情速览（固定区块）

个人版在计数条之后、可排序模块之前，固定渲染一个「病情速览」区块，用来回答“这是谁、有什么病、哪里不正常”。它**不参与 `focus` 与 `section_order` 排序**，永远在最前，包含四组内容：

| 内容 | 数据来源 | 展示规则 |
|---|---|---|
| 诊断 | `visits.diagnosis`，**不受最近天数时间窗限制** | 同一 `diagnosis` 字段内以 `；`/`;` 分隔的多条诊断拆成独立标签，每个标签都是原文子串；逗号不拆分（`原发性高血压（3级，极高危）` 是一条）；同一诊断重复出现时只保留最近一次就诊 |
| 报告标记的异常 | `lab_results.items` 中带 H/L 等显式标记的检验项，同样不看时间窗 | **逐项完整列出，不截断**；名称、数值、单位、参考范围原样转写；不同报告的同一指标各自保留 |
| 阈值告警 | `health_advisor` 的 `health_tips` 中 `type=metric_anomaly` 且 `severity` 为 alert/warning 的条目 | 带测量值与参考范围一起展示，是唯一尊重用户自定义阈值的路径 |
| 既往史 / 过敏史 | `members.medical_history` / `members.allergies` | 原文转写 |

四组内容全为空时整块不渲染，不显示空状态面板。

**异常的两个来源必须分开呈现**，不能合并计数或互相替代：报告标记来自化验单本身印出的 H/L，阈值告警来自已配置范围（含用户自定义），二者语义不同。卡片不推断异常，也不因数值看起来偏高就把未标记项列为异常。

个人版计数条的四个数字口径互不重叠：警告数只统计 alert/warning 级提示，提醒数只统计 warning 级，明确异常数只统计报告标记项，待处理提醒数只统计到期提醒。报告标记的异常**不计入**警告数或提醒数。

页眉还会展示性别与年龄：有出生日期时用精确年龄，只有 `age_years` 时按 `age_recorded_at` 向前推算并标注记录日期，两者都没有则整段省略，**不由年龄反推出生日期**。同时有出生日期与年龄时以出生日期为准。

使用返回的 `layout_profile` 做验证和自然语言概括，不要把它原样发给用户。个人版至少检查 `focus`、`section_order`、`metrics_window_days` 和 `snapshot`（`snapshot` 给出诊断数、报告数、异常项数、阈值告警数以及是否记录了既往史/过敏史；`metrics_window_days` 是趋势图实际取数的天数，用于说明图上的日期跨度）；家庭版检查 `focus`、`member_order` 和 `featured_member`。
